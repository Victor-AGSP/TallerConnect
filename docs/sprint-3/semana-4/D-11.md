# D-11 — Gateway de integración obsoleta y entornos sin separar

Fecha: 2026-11-24. Rama `Victor`, base `17fc162`. **Estado: PARCIALMENTE RESUELTO.** La integración está corregida. La producción sigue usando una dirección obsoleta hasta que el equipo apruebe el cambio, así que el defecto **no está cerrado**.

Origen: [SCRUM-164](../semana-3/SCRUM-164.md) (sondas), [SCRUM-226](../semana-3/SCRUM-226.md) (impacto en Android), [SCRUM-227](../semana-3/SCRUM-227.md) (cambio propuesto), [SCRUM-230](SCRUM-230.md) (riesgo P1).

## Causa

1. `API_GATEWAY_URLS.INTEGRATION` y `PRODUCTION` apuntaban a `https://tallerconect.vercel.app/api`, que responde `404 x-vercel-error: DEPLOYMENT_NOT_FOUND`.
2. `resolveApiUrl` devolvía `INTEGRATION` tanto para `integration` como para `production`: la constante `PRODUCTION` no se usaba, de modo que no se podía cambiar un entorno sin cambiar el otro.

## 1. Corrección de integración (aplicada)

`src/config/env.ts`:

```diff
-  INTEGRATION: 'https://tallerconect.vercel.app/api',
+  INTEGRATION: 'https://api-tallerconnect.inf.uct.cl/api',
   PRODUCTION: 'https://tallerconect.vercel.app/api',   // sin cambios (pendiente de aprobación)
...
-  if (env === 'integration' || env === 'production') {
-    return API_GATEWAY_URLS.INTEGRATION;
-  }
+  if (env === 'integration') {
+    return API_GATEWAY_URLS.INTEGRATION;
+  }
+  if (env === 'production') {
+    return API_GATEWAY_URLS.PRODUCTION;
+  }
```

`EXPO_PUBLIC_API_URL` sigue teniendo la máxima prioridad. Desarrollo local y emulador Android no cambian. `buildGatewayEndpointPath` usa `INTEGRATION` solo como base por defecto para detectar el sufijo `/api`; ambas URLs terminan en `/api`, por lo que su comportamiento no cambia.

URL efectiva según la configuración (sin `.env` privados):

| `EXPO_PUBLIC_APP_ENV` | `EXPO_PUBLIC_API_URL` | Plataforma | URL efectiva |
| --- | --- | --- | --- |
| cualquiera | definida | cualquiera | la explícita, sin barras finales |
| `integration` | — | cualquiera | `https://api-tallerconnect.inf.uct.cl/api` (**nuevo**) |
| `production` | — | cualquiera | `https://tallerconect.vercel.app/api` (sin cambios; retirada) |
| `development`, ausente o desconocido | — | android | `http://10.0.2.2:8000/api` |
| `development`, ausente o desconocido | — | ios / web | `http://localhost:8000/api` |
| `test` (Jest) | — | — | `http://localhost:8000/api` |

Despliegue Kubero (rama `deploy/kubero-frontend`, no modificada): `APP_ENV=integration` con `EXPO_PUBLIC_API_URL=https://frontend-movil.inf.uct.cl/api` explícita, proxy Nginx a la Gateway UCT. Este cambio no le afecta.

## 2. Configuración de producción (pendiente de aprobación)

`API_GATEWAY_URLS.PRODUCTION` conserva `https://tallerconect.vercel.app/api`. Una compilación con `EXPO_PUBLIC_APP_ENV=production` y sin URL explícita **no funciona**. Reemplazarla exige que el equipo confirme cuál es la Gateway de producción: no hay evidencia de que la Gateway UCT de integración sea también producción. Una prueba fija el valor actual para que el cambio sea explícito. Mitigación hasta entonces: definir `EXPO_PUBLIC_API_URL` en cada compilación.

## 3. Configuración privada local (pendiente de revisión, no modificada)

Los archivos `.env` y `.env.local` no se versionan (`.gitignore`) y no se tocaron. Solo se revisaron las claves públicas. Ambos definen `EXPO_PUBLIC_APP_ENV=production` y `EXPO_PUBLIC_API_URL=https://tallerconect.vercel.app/api`. Como la URL explícita tiene prioridad, **siguen enviando la app local a la Gateway retirada pese a esta corrección**: la exportación con configuración local cargó `.env.local .env`.

Resolución manual recomendada (decisión del propietario de la máquina):

```dotenv
EXPO_PUBLIC_APP_ENV=integration
# Eliminar EXPO_PUBLIC_API_URL, o fijarla a la Gateway UCT:
# EXPO_PUBLIC_API_URL=https://api-tallerconnect.inf.uct.cl/api
```

Alternativa sin editar archivos: `EXPO_NO_DOTENV=1 EXPO_PUBLIC_APP_ENV=integration npx expo start`, o exportar `EXPO_PUBLIC_API_URL` en el shell (las variables ya definidas no se sobrescriben).

Riesgo de configuración contradictoria: mantener `APP_ENV=production` y quitar solo la URL llevaría al valor de producción retirado, no a integración. Hay que cambiar ambas claves juntas.

`.env.example` (plantilla versionada): la opción B ahora indica la Gateway UCT y advierte sobre `production`. Su valor activo sigue siendo `localhost`.

## 4. Pruebas

`__tests__/env-config.test.ts`: de 14 a 28 pruebas. Cubren:

- integración usa la Gateway UCT en ios, android y web;
- producción conserva su constante;
- integración y producción se resuelven de forma independiente;
- la URL explícita prevalece en todos los entornos;
- una URL explícita vacía no anula la resolución por entorno;
- un entorno desconocido nunca resuelve a la nube;
- normalización de barras finales y no duplicación de `/api`;
- HTTPS en las Gateways de la nube;
- los mocks no se activan sin banderas;
- `ENV.API_URL` real cargando el módulo con variables de entorno (`jest.isolateModules`).

Se actualizó una sola expectativa existente: «integración = Vercel» se convirtió en «integración = UCT». Era el requisito que cambió. Las cadenas Vercel que quedan en `buildGatewayEndpointPath` y en las pruebas de normalización son entradas de texto arbitrarias y no dependen del despliegue.
