No se afirma que exista un endpoint exclusivo de resumen administrativo. `admin-dashboard.service.ts` es un agregador legacy con fallback demo y **no es el consumidor del panel actual**. No se usa su fallback como evidencia real.

El [layout admin](<../../src/app/(admin)/_layout.tsx>) exige rol Administrador. Eso no implica que todos sus endpoints sean exclusivos: el [análisis del contrato MS3](../visibilidad-campos-por-rol.md) no especifica los roles de lectura de repuestos/proveedores, y el mecánico puede consultar presupuestos según alcance backend. La prueba de prohibición debe hacerse solo donde el contrato/QA defina exclusividad. No se inventa un 403 obligatorio para esos recursos. Cliente y Mecánico sí deben quedar fuera del grupo UI administrativo; esa guarda se ejecutó con mocks, queda pendiente con sesión real.

## Defectos corregidos y validaciones

El reintento del panel llamaba `setIsLoading` sin declararlo, produciendo error TypeScript y fallo en tiempo de ejecución. Se incorporó estado de carga real y una presentación de carga hasta recibir respuestas; se movieron los cambios síncronos a los eventos de recarga, manteniendo efectos como inicio de solicitudes. Se aplicó la misma separación al listado administrativo de órdenes para resolver los dos errores de lint existentes.

[admin-query-states.test.tsx](../../__tests__/admin-query-states.test.tsx) agrega cuatro pruebas funcionales: carga inicial y recuperación de error para panel y listado. En [vehicle-list-integration](../../__tests__/vehicle-list-integration.test.tsx) se aisló notificaciones en la prueba de navegación: los avisos derivados agregaban una segunda consulta de órdenes fuera del propósito de esa prueba (fallo observado en SCRUM-217). En [admin-notice-validation](../../__tests__/admin-notice-validation.test.ts) se ajustaron dos expectativas de texto al error tipado que ya emite el mapper; sigue exigiéndose el rechazo de estados desconocidos.

[Resultado de 7 suites](evidencias/SCRUM-219-tests.json): **99 PASS, 0 FAIL**, con mocks y corrección de utilidad de rutas de SCRUM-158 aún sin commit. `CI=1 npm run lint`: exit 0, **0 errores y 46 advertencias previas**. `npm run typecheck`: persisten solo tres errores de reexportaciones desde evidence.service en `src/services/index.ts`, registrados para SCRUM-157; el error del panel ya no aparece. [Registro de herramientas](evidencias/SCRUM-219-herramientas.txt).
